Turning scraped data into clean, structured outputs

Author Amin Farahani
Published October 14, 2026
Reading time 5 min read

Collecting pages is the easy half of web scraping. The value is in what comes out the other end: rows that a sales team, a dashboard or another API can use without cleaning them again. Working on product, business and location data for sources like Torob, Google Maps and Neshan, I settled on a pipeline that keeps every stage simple and re-runnable.

1. Split the job into stages

Fetch → parse → normalize → validate → store → export. Each stage reads the output of the previous one, so a bug in parsing never means downloading everything again. I always keep the raw response (HTML or JSON) next to the parsed record — when the parser improves, I re-run it over the archive.

2. Fetch politely and predictably

Before writing code, read the site's terms and robots.txt, and prefer an official API whenever one exists. Then limit concurrency, add delays, cache responses and retry transient failures with exponential backoff:

async function fetchWithRetry(url, tries = 4) {
  for (let i = 0; i < tries; i++) {
    const res = await fetch(url, { headers: { Accept: "application/json" } });
    if (res.ok) return res;
    // only 429 and 5xx are worth retrying
    if (res.status !== 429 && res.status < 500) throw new Error(`HTTP ${res.status}`);
    const wait = 500 * 2 ** i + Math.random() * 300; // backoff + jitter
    await new Promise((r) => setTimeout(r, wait));
  }
  throw new Error(`Gave up on ${url}`);
}

3. Prefer structured sources over CSS selectors

Selectors break on every redesign. Many pages already ship their data in a structured form: JSON-LD blocks (script[type="application/ld+json"]), framework state such as __NEXT_DATA__, or the JSON endpoints the page itself calls. Parse those first and fall back to the DOM only when you must.

4. Normalize — especially Persian text

Iranian sources mix Persian, Arabic-Indic and Latin digits, Arabic and Persian letters, and prices in both Rial and Toman. If you don't normalize, "the same" shop shows up three times. A small set of helpers removes most of the noise:

const FA = "۰۱۲۳۴۵۶۷۸۹";
const AR = "٠١٢٣٤٥٦٧٨٩";

export function normalizeText(s = "") {
  return s
    .replace(/[۰-۹]/g, (d) => FA.indexOf(d))   // Persian digits  → 0-9
    .replace(/[٠-٩]/g, (d) => AR.indexOf(d))   // Arabic digits   → 0-9
    .replace(/ي/g, "ی").replace(/ك/g, "ک")     // Arabic letters  → Persian
    .replace(/\u200c+/g, "\u200c")            // collapse repeated ZWNJ
    .replace(/\s+/g, " ")
    .trim();
}

export function normalizePhone(raw) {
  const d = normalizeText(raw).replace(/\D/g, "");
  if (d.startsWith("98")) return "+" + d;
  if (d.startsWith("0")) return "+98" + d.slice(1);
  return null;
}

Pick one currency unit for storage (I use Toman, where 1 Toman = 10 Rial) and convert at parse time, keeping the original string for audits.

5. Validate every record — and keep the rejects

A schema turns silent garbage into visible errors. With zod, a place record might look like this:

import { z } from "zod";

const Place = z.object({
  name: z.string().min(2),
  category: z.string(),
  phone: z.string().regex(/^\+98\d{10}$/).nullable(),
  lat: z.number().min(24).max(40),   // rough bounding box of Iran
  lng: z.number().min(44).max(64),
});

Records that fail validation go to a separate table with the reason. That list is the best to-do list for improving the parser.

6. Deduplicate with stable keys

  • Products: the source's own id or a canonical URL.
  • Places: normalized name + coordinates rounded to 4 decimals (about 11 m).
  • Upsert instead of insert, and keep first_seen / last_seen timestamps — price and status history come for free.

7. Export for the people who will use it

  • CSV with a UTF-8 BOM — without it, Excel shows Persian text as gibberish.
  • JSON for other services, with a documented schema.
  • Google Sheets when a non-technical team needs to filter and comment.
Takeaway: a scraper is finished when its output can be trusted without a second cleanup pass. Normalization, validation and deduplication are where that trust comes from.
