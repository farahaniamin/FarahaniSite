Custom WooCommerce features without plugin bloat

Author Amin Farahani
Published October 22, 2026
Reading time 5 min read

Many slow WooCommerce stores have the same story: every small request — one extra checkout field, a quantity discount, a warranty label — became another plugin. Forty plugins later the admin is sluggish, updates are scary and nobody knows which one breaks checkout. On the stores I build, small features live in one site-specific plugin, written against WooCommerce's own hooks.

1. One site-specific plugin (not functions.php)

Code in a theme's functions.php disappears when the theme changes. A tiny plugin survives redesigns and can be versioned in Git. Declare compatibility with High-Performance Order Storage (HPOS) from day one:

<?php
/**
 * Plugin Name: Store Customizations
 * Description: Site-specific WooCommerce features.
 */
defined( 'ABSPATH' ) || exit;

add_action( 'before_woocommerce_init', function () {
    if ( class_exists( \Automattic\WooCommerce\Utilities\FeaturesUtil::class ) ) {
        \Automattic\WooCommerce\Utilities\FeaturesUtil::declare_compatibility( 'custom_order_tables', __FILE__, true );
    }
} );

With HPOS, read and write order data through wc_get_order() and $order->get_meta() / update_meta_data() — never get_post_meta() on orders.

2. Checkout fields with a filter

On the classic (shortcode) checkout, adding or removing fields is a single filter, and saving the value is one action:

add_filter( 'woocommerce_checkout_fields', function ( $fields ) {
    unset( $fields['billing']['billing_company'] );

    $fields['billing']['billing_national_code'] = array(
        'label'    => 'National code',
        'required' => false,
        'priority' => 35,
    );
    return $fields;
} );

add_action( 'woocommerce_checkout_create_order', function ( $order, $data ) {
    if ( ! empty( $data['billing_national_code'] ) ) {
        $order->update_meta_data( '_national_code', $data['billing_national_code'] );
    }
}, 10, 2 );

Stores on the block-based Checkout use the Additional Checkout Fields API (woocommerce_register_additional_checkout_field()) instead — check which checkout the store runs before writing code.

3. Custom product data in the admin

add_action( 'woocommerce_product_options_general_product_data', function () {
    woocommerce_wp_text_input( array(
        'id'    => '_warranty_months',
        'label' => 'Warranty (months)',
        'type'  => 'number',
    ) );
} );

add_action( 'woocommerce_admin_process_product_object', function ( $product ) {
    if ( isset( $_POST['_warranty_months'] ) ) {
        $product->update_meta_data( '_warranty_months', absint( $_POST['_warranty_months'] ) );
    }
} );

Display it on the product page with a small callback on woocommerce_single_product_summary — no page-builder widget required.

4. Pricing rules in a few lines

A "10% off when you buy 10 or more" rule doesn't need a dynamic-pricing suite:

add_action( 'woocommerce_before_calculate_totals', function ( $cart ) {
    if ( is_admin() && ! defined( 'DOING_AJAX' ) ) {
        return;
    }
    foreach ( $cart->get_cart() as $item ) {
        if ( $item['quantity'] >= 10 ) {
            $product = $item['data'];
            // base it on the regular price, so repeated runs never stack the discount
            $product->set_price( (float) $product->get_regular_price() * 0.9 );
        }
    }
} );

5. Move heavy work to the background

Syncing an order to an ERP, sending it to a shipping API or generating an invoice should never slow down the customer's checkout. WooCommerce ships with Action Scheduler, so background jobs need no extra plugin:

add_action( 'woocommerce_order_status_processing', function ( $order_id ) {
    as_enqueue_async_action( 'store_sync_order', array( 'order_id' => $order_id ) );
} );

add_action( 'store_sync_order', function ( $order_id ) {
    $order = wc_get_order( $order_id );
    // call the external API here; failures are logged and can be retried
} );

6. Measure before and after

  • Query Monitor shows slow queries, hooks and HTTP calls per page.
  • Check the size of autoloaded options — WordPress 6.6+ warns about it in Site Health.
  • Cache expensive queries in transients, and add a Redis object cache on busy stores.
Takeaway: plugins are great for big, maintained integrations — payment gateways, shipping, SEO. For small, store-specific behaviour, a few well-placed hooks are faster, safer and easier to maintain.
